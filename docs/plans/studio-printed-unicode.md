# Printed Unicode positioning preflight (round 40)

Courier Prime contains U+0326 (combining comma below) with zero advance width. A font character-set check therefore succeeds even though Studio's fixed code-point column layout and PDF text drawing cannot guarantee its placement. Supported glyphs alone are insufficient evidence of correct typesetting. Soft hyphens and other Unicode formatting controls likewise require invisible, discretionary or directional behavior that this layout does not model.

`printedTypographyProblem` conservatively checks Unicode `Mark` and `Cf` categories in the final layout's printable runs. The layout adds one actionable warning; `screenplayPdf` runs the same preflight after the existing malformed-source guard and before creating a PDF or loading fonts. Both full screenplay and actor-side exports use this path. Preview remains available for source repair, with an explicit warning that its spacing may differ. This does not introduce automatic normalization, strip any characters, or claim multilingual shaping support.

The diagnostic lists at most eight distinct code points, labels each as a combining mark or formatting character, and stops scanning after a ninth distinct problem. Repeated characters consume no extra diagnostic memory. It includes printed title text, scene numbers and synthetic side covers; omitted notes, boneyards, outlines and excluded title fields never reach the check. Precomposed supported letters such as é remain exportable. Source can always remain in Fountain or a Studio backup; replacing a combining sequence with a precomposed letter is an explicit author choice where an equivalent supported letter exists.

Ten focused tests demonstrate the actual embedded font's U+0326 support and zero advance, refusal before font fetch, formatting controls including soft hyphen and bidi isolates, spacing/enclosing/supplementary marks, bounded diagnostics, privacy exclusions, title/scene-number checks, and full/actor-side PDFs with precomposed é. Existing actor-side canonical-name tests now expect the warning for a preserved decomposed cue, while still confirming correct character grouping and exact cue text. A live 320px Chromium check also confirmed visible warnings, no unsupported PDF download, unchanged source, successful café/private-mark export, native Tab focus and End-key scrolling for both overflowing warning regions, and zero WCAG axe findings. Physical browser/print and external reader validation remain separate release gates.
