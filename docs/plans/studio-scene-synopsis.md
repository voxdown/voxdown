# Scene card synopses

Scene cards offer **Add synopsis…** or **Edit synopsis…**, followed by explicit Preview and Apply. Each entered line becomes a Fountain `= synopsis` line; these remain portable outline content and do not print in screenplay exports. Blank text removes the block. Private `[[notes]]` and `/*omissions*/` are separate and never promoted to public synopsis text.

`planSceneSynopsis(source, sceneIndex, value)` returns a `SceneSynopsisPlan` with `kind: "synopsis"`, one atomic change (or none), complete candidate source, exact before/after source preview, and the original scene index. `SceneEditPlan` unifies this with existing `kind: "move"` plans. Indexes refer only to the exact captured source. The Scene board captures a copy of source/id when opened, checks freshness before preview/apply, and passes that snapshot to the existing apply callback. The host must retain its authoritative source/id guard and isolated history transaction so Undo restores the complete previous source.

New blocks go immediately after the scene heading. One existing contiguous block is replaced at its existing position. Dispersed blocks and lines containing private comment fragments require source editing: the dialog explains this, disables editing, and never reconstructs those lines from visible text. Section synopses remain untouched. Exact scene numbers, headings, body, other synopses, private bytes, title/front matter, and surrounding line endings remain intact. Heading-only EOF, BOM, CRLF/CR/LF, internal empty synopsis lines, removal and no-op spelling preservation are supported. A private passage crossing the insertion boundary is rejected.

Input is bounded to 10,000 characters/100 lines and rejects control/bidi characters and private-comment delimiters. Each candidate is parsed again: unchanged physical lines must retain their roles/content and private omissions must retain exact bytes and mapped boundaries. A role-changing edit fails rather than silently reinterpreting neighboring dialogue/action. Preview uses textContent, including literal Fountain syntax; nothing is interpreted as HTML. Parsing occurs on opening an editor and explicit Preview, not on every keystroke. Search renders at most 50 scene cards per page.

Style hooks: `.scene-synopsis-editor` (fieldset/textarea) and `.scene-synopsis-preview` (headings and exact-source `pre` elements). The host should constrain widths and wrap long preview lines for narrow screens. No network, storage, or publication is involved.

Validation: `studio-scene-synopsis.test.ts` covers private boundaries, malformed omissions, controls, Unicode, numbering/sections, BOM/newlines/EOF, multiline/removal/no-op, bounds, one-step undo and a 2,000-scene source. `studio-scene-board.test.ts` runs isolated Chromium for exact previews, edit invalidation, snapshot guards, private/dispersed rejection, no-op/removal/rejected apply, capped cards and close/reopen cleanup. Physical-device behavior is not claimed by these tests.
