## Actual independent producer

`abf0d0800ab0b9dfd5bbe780137641e746afbad4`, using its real Fountain parser and

## Reproduce

From the repository root, with Python 3 and its standard-library `venv` module:

```sh
python3 scripts/generate-studio-screenplain-interop.py --check
pnpm exec vitest run site/test/studio-screenplain-interop.test.ts
```

To intentionally regenerate, omit `--check` and review the resulting fixture
diff. A changed upstream archive checksum fails closed; do not update the pin
or checksum without reviewing the producer change. No third-party screenplay
or third-party source is vendored in the repository.

## Observations and contract

The original 29-line Lantern fixture contains scene headings, action, normal
and overlapping dialogue, parentheticals, centered action, transition,
multi-line text, bold/italic/underline and combined emphasis, `& < >`, accented
Latin and CJK text, scene numbers, title metadata, a private note, and boneyard.

Four automated tests pass:

1. Inspect the independently generated FDX with browser DOMParser and compare
   every visible character, style flag, role, and dual cue to the original
   fixture, accounting explicitly for producer omissions.
2. Import Screenplain FDX in Studio and retain those public semantics without
   activating any private syntax.
3. Export the original source using Studio, inspect XML with the independent
   DOM oracle, and match Screenplain's public semantics plus Studio's retained
   scene numbers.
4. Import and re-export Screenplain FDX without changing public XML semantics;
   verify Studio's own numbered export imports correctly and omits title
   metadata with a report.

The XML oracle does not call the Studio importer to infer expectations. It
normalizes paragraph grouping, newline placement and adjacent Text nodes
because these producers group multiline dialogue differently; it retains
character-level style and whitespace within each nonempty physical line.
Empty-line spacing and layout are outside this fixture's assertion.

Observed producer limitations:

- Screenplain parses `#12A#` and `#13#`, but this FDX exporter does not write
  a `Number` attribute. Studio cannot recover absent scene numbers. Studio's
  own export retains both values, verified independently.
- Screenplain does not emit a TitlePage. Its title/contact are already absent
  before Studio imports the file. Studio independently reports title metadata
  exclusion when importing its own export containing a TitlePage.
- Both exports omit this fixture's private note and boneyard. The fixture uses
  well-formed private syntax; separate Studio security tests cover malformed
  and nested forms.

No Studio compatibility defect was found in this representative supported
subset. Unsupported FDX structure continues to fail with a readable error;
this evidence is not a reason to weaken that contract. The next distinct
validation would be a licensed native Final Draft open/save check and another
independent producer's supported export, with source-authorized fixtures.
