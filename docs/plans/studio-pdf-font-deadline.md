# Bounded PDF font loading

Round 31 repairs a recoverability issue found during release review. The font fetch previously had no application deadline: a connection that stalled before response headers, or after headers while delivering the body, could keep full PDF export in “Making PDF…” indefinitely. Actor sides could be closed, but the shared unresolved font promise could poison later retries.

`pdf.ts` now creates a same-origin font loader with a 15-second deadline covering both `fetch` and `response.arrayBuffer()`. Timeout aborts the native request/body reader. All failure paths abort any remaining response, evict the failed promise and clear its timer. Explicit subsequent export starts a fresh request. Concurrent requests for the same font share one promise; successful byte buffers remain cached. Different font requests each settle within their deadline. HTTP errors, redirects and synchronous transport failures also leave retries available.

The loader rejects cross-origin URLs before transport and retains `mode: same-origin`, same-origin credentials and `redirect: error`. Public error messages contain no font response body or screenplay source. It never falls back to a different font, cloud service or synchronous network request. Source, editor state and file/download recovery guards are untouched. Prepared offline sites retain their existing faster service-worker cache fallback.

`createFontLoader(timeoutMs = 15_000)` exposes a scoped cache factory for native browser transport tests. The production PDF exporter uses its default deadline; the UI has no timeout tuning setting. On failure, existing export cleanup restores the full PDF button and actor-sides retry controls.

Eight isolated Chromium tests execute the real loader against a real local HTTP server, with only PDF composition dependencies stubbed. They exercise held headers, headers flushed with stalled body, concurrent caller settlement and socket closure, retry/cache success, HTTP/redirect failure, four simultaneous font deadlines, same-origin enforcement, synchronous transport failure and timeout validation. A live Studio smoke test confirms a held font request restores the full PDF button after timeout, an explicit retry downloads a real PDF, and the original Fountain source remains exact. The smoke accelerates only the production 15-second timer to avoid waiting during the check; native transport tests use the loader's injectable short deadline.

Before-fix native browser reproduction: `/tmp/studio-font-stall-before.mjs` demonstrated both headers/body reads remained pending, matching the absence of a deadline in the old implementation. Post-fix live check: `/tmp/studio-font-retry-live.mjs`. Production offline and broader PDF checks remain with the independent reviewer; these tests do not certify native printer or third-party PDF reader behavior.
